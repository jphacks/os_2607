# Domain

## 用語

| 用語 | 定義 |
| --- | --- |
| Person | アプリ内で識別する人。アプリ固有の永続IDであるpersonIDを持つ。端末や通信セッションとは別の概念。 |
| Profile | Personのプロフィール。本人が公開を許可した情報だけを扱い、最新情報の正本はSupabaseに置く。 |
| Proximity | 特定の相手との距離・方向と観測時刻を表す観測情報。取得できない値は不明として扱う。 |
| Encounter | 近接条件に基づいて開始・終了する、特定のPersonとの遭遇区間。履歴と累計時間の根拠になる。 |
| Reveal | 相手との累計Encounter時間に応じたプロフィール項目の開示判定。公開許可も満たす必要がある。 |
| Connection | 端末発見・接続・識別情報交換を含む通信状態。接続の成立だけではEncounterの成立を意味しない。 |

## 識別と情報の扱い

- personIDはアプリ固有の永続ID。再接続後も同じPersonの履歴を参照するために使う。
- discoveryTokenはNearby Interactionのセッションに関係する情報であり、永続的なユーザーIDに使わない。
- 通信peer、token、personIDの対応は通信側で管理し、DomainにはpersonIDとSDKに依存しない観測値を渡す。
- personIDの受信だけで本人確認が完了したとはみなさない。認証との対応は未決定。
- 累計時間は相手Personごとに扱う想定。複数端末間や双方の端末間での集計方法は未決定。

## 仮ルール（変更可能・確定仕様ではない）

| 対象 | 仮条件 | 結果 |
| --- | --- | --- |
| Encounter開始 | 距離が2m以内の状態が10秒続く | Encounter開始 |
| Encounter終了 | 距離が3mを超えた状態が15秒続く | Encounter終了 |
| Reveal | 累計60秒以上 | 趣味1を開示可能 |
| Reveal | 累計180秒以上 | 趣味2を開示可能 |
| Reveal | 累計300秒以上 | 会話のきっかけを開示可能 |

「2m以内」は2mを含み、「3mを超える」は3mを含まない。開始・終了で異なる閾値を使い、境界付近での頻繁な切り替えを抑える想定。閾値や項目は一箇所で変更できる設計を目指す。

Revealは公開許可がある項目だけに適用する。条件達成によって未公開情報の取得や表示が許可されるわけではない。公開許可と段階的な開示条件を分けて扱う。

## Open Questions

- 開始条件の2m・10秒、終了条件の3m超・15秒は実環境で適切か。
- Revealの60秒・180秒・300秒と、趣味1・趣味2・会話のきっかけという順序は適切か。
- 開始待機の10秒、終了待機の15秒を累計時間に含めるか。開始・終了時刻をどこに置くか。
- 2m超から3m以内の間の時間をどう加算し、待機中のタイマーをどう扱うか。
- 観測欠損、古い観測、測距停止、通信切断、バックグラウンド移行時に連続性をどう判定するか。
- 再起動時に未終了Encounterを終了・再開・破棄のどれとして扱うか。
- 累計時間の端数処理、重複・重なったEncounterの排除、時計変更時の扱いはどうするか。
- Revealは一度成立したら維持するか。履歴削除やプロフィールの公開撤回時はどう扱うか。
- personIDの発行、保存、再インストール時の復元、複数端末・認証アカウントとの対応をどうするか。
